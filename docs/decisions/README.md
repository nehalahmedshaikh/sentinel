# Architecture Decision Records

This directory contains Architecture Decision Records (ADRs).

ADRs document consequential architectural and technology decisions.

Each record should include:

1. Title and status.
2. Context and problem.
3. Decision.
4. Alternatives considered.
5. Rationale.
6. Consequences and trade-offs.

Use sequential numbering:

- 0001-meaningful-decision-name.md
- 0002-another-decision.md

Suggested statuses:

- Proposed
- Accepted
- Superseded
- Rejected

Do not create an ADR for every minor implementation choice.

Record decisions that materially affect system architecture, interfaces,
dependencies, persistence, reliability or maintainability.
